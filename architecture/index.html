Section 01
MLOps Governance Lifecycle
Every model change moves through six stages before it can reach production — evaluated, gated, and reversible.
Stage 1

Prompt / Model Edit

  • Modelfile changed
  • New candidate built
Stage 2

Staged Tag

  • prm-<sha> build
  • Never overwrites :latest
Stage 3

Champion/Challenger

  • A/B vs live model
  • Same testset, both sides
Stage 4

LLM-as-Judge Gate

  • 0.70 pass threshold
  • Substance, not grammar
Stage 5

Promote + Snapshot

  • Pre-promotion snapshot
  • Rollback path proven
Stage 6

Drift Watch

  • Weekly automated check
  • Parameter-order safe
6/7
Agents passed the real gate cycle
0.667
Held-back score vs. 0.70 threshold

Real cycle, not simulated — a genuine gate failure

The job-fit agent scored a mismatched candidate 95/100 while its own reasoning said otherwise — an arithmetic self-contradiction. The gate held it back at 0.667, it was root-caused and re-prompted, and it re-evaluated to 0.967 before promotion. The pre-fix version is still visible in the live model registry today.

Known Gaps & Open Decisions
Tracked openly in the project's own documentation rather than glossed over — this is what a reference build honestly looks like.
  • 1

    DB persistence. Several DB-backed containers still sit on plain container-root disk rather than decoupled named volumes — a rebuild would take the data with it.

  • 2

    GPU contention grew. Three consumers (Ollama, SwarmUI, a k3s Triton node) now share two physical GPUs, up from two — no load policy has been exercised yet.

  • 3

    mgmtbr0 is unexplained. An unmanaged, unused bridge with no documentation trail — flagged rather than ignored.

  • 4

    Flowise sits empty. The real agent-orchestration effort moved to a separate project instead — worth a deliberate decision on Flowise's future.

  • 5

    The AppSec stack is new. Semgrep/Trivy/Gitleaks/SonarQube/DefectDojo are deployed but haven't produced a real finding yet — this section will update once they have.

Why list these at all

Credibility over polish

A reference build with no listed gaps is less believable than one with a maintained, dated punch list.

Single-operator honesty

This matches the portfolio's own scope statement: reference-implementation evidence, not scale/production.
